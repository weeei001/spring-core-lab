# 手動驗收與 BUG 複測案例

狀態：以下案例尚未執行。建置或測試生命週期成功不代表這些流程已驗收。

## 前提

- 使用本機獨立測試資料庫，建立空白結構並套用已核准的手動驗收 schema；不要使用既有業務資料。準備測試專案 P、另一專案 Q，以及 P 的兩個驗收項目 X、Y。
- 準備 P 的可讀寫成員、僅具 `project:read` 的成員、非 P 成員，以及具有所需權限的管理者。P 處於可寫狀態；另準備結案專案驗證唯讀。
- 記錄實測程式版本、環境、操作帳號、批次及任務 ID。附件使用合成截圖，避免使用真實業務資料。
- 建立 A 版驗收批次，填入測試環境及項目的步驟與預期結果。每次記錄結果時明確填入實測版本。

## 案例

| ID | 操作 | 預期結果 | 實際結果 |
| --- | --- | --- | --- |
| QB-01 | X 新增 A 版 FAIL，填實際現象；從失敗紀錄選擇建立 BUG。檢查並修改預填內容後確認建立。 | 建立前可確認標題與內容；內容包含重現步驟、預期／實際結果、環境、實測版本及來源連結。建立後該失敗紀錄連到同專案 BUG；任務詳情可回到來源。 | 未執行 |
| QB-02 | 在 BUG 任務上新增合成截圖附件，開啟失敗紀錄與任務詳情的來源連結。 | 截圖保存在既有任務附件；來源連結可找到對應批次、項目及失敗紀錄。 | 未執行 |
| QB-03 | Y 新增 A 版 FAIL，選擇連結 QB-01 的既有 BUG；另嘗試連結 Q 的 BUG 與 P 的非 BUG 任務。 | Y 連到同一 BUG，沒有建立第二張任務；跨專案、非 BUG 與已刪除任務不能作為新連結。 | 未執行 |
| QB-04 | 開發者將該 BUG 改為 REVIEW，重新載入 X、Y 的結果與批次統計。 | BUG 為 REVIEW（既有畫面顯示「審核中」），代表等待複測；X、Y 仍為 FAIL，A 版紀錄未變，統計按各項最新結果顯示失敗。 | 未執行 |
| QB-05 | X 新增 B 版 FAIL，填入仍失敗的現象並連到既有 BUG。由有 `task:write` 的成員明確將 BUG 改為 IN_PROGRESS。 | A、B 兩筆結果及各自版本、現象保留；B 成為 X 最新結果。新增 FAIL 不會靜默改任務狀態，明確操作後 BUG 才為 IN_PROGRESS，沒有新建 BUG。 | 未執行 |
| QB-06 | 開發者修復後將 BUG 改為 REVIEW；X 新增 B 版 PASS，接著由有 `task:write` 的成員明確將 BUG 改為 DONE。 | PASS 不會靜默改任務狀態；明確操作後 BUG 為 DONE。X 最新結果為 PASS，Y 仍為 FAIL；所有先前結果可讀。 | 未執行 |
| QB-07 | 重新載入批次及任務詳情，查看共用 BUG 的兩個來源；另新增未測與 BLOCKED 項目。 | 詳情列出 X、Y 的關聯失敗紀錄。統計依每個項目的最新結果分別顯示未測、通過、失敗、受阻筆數；不以完成率掩蓋受阻項目。BUG 的 DONE 不會將 Y 改成 PASS。 | 未執行 |
| QB-08 | 僅讀成員查看失敗紀錄與 BUG 來源，嘗試記錄結果、連結或建立 BUG、修改狀態；非成員直接請求同一批次及 BUG 反查 API。 | 僅讀成員可讀但寫入受拒；非成員不可讀取或寫入 P 的資料。管理者仍需對應讀寫權限；結案專案可讀、寫入受拒。 | 未執行 |
| QB-09 | 模擬 BUG 建立成功後連結請求失敗，保留建立成功的任務 ID，再以該 ID 重試連結。 | 顯示連結失敗與已建立的任務 ID；重試連到原 BUG，沒有重複建立，失敗紀錄原有事實不變。 | 未執行 |

## 實測紀錄

執行時逐項填入日期、版本、環境、帳號、批次／項目／BUG ID、實際結果與證據位置；失敗保留原紀錄，再新增修補版複測結果。若登入、服務或工具受阻，記下受阻步驟及錯誤，不將未執行案例標為通過。
